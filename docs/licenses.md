# サードパーティ製ライセンス情報の同梱について

このアプリが利用しているオープンソースソフトウェア（OSS）のライセンス情報を、
ビルド成果物に同梱し、アプリ内から閲覧できるようにする仕組みについて説明します。

## 1. なぜ同梱が必要か

このアプリは **完全オフライン・端末内完結** をうたっています。Web版は
Service Worker のキャッシュにより電波の無い場所でも動作し、APK版に至っては
`android.permission.INTERNET` 権限自体を持たないため、そもそも外部と
通信できません（詳細は [`docs/apk.md`](apk.md) の「7. `INTERNET` 権限に
ついて」を参照）。

一方で、このアプリは React・zxing-wasm（バーコード読み取りエンジン）・
Google ML Kit（OCRエンジン）など、複数のOSSライブラリ／ライブラリ由来の
配布物を利用しており、それぞれのライセンス（MIT・Apache-2.0 など）は
著作権表示・ライセンス本文の同梱を求めています。

「ライセンス情報は各ライブラリの GitHub ページを見てください」という
外部リンク方式は、通信できない前提のこのアプリでは実質的に「ライセンス情報を
提供していない」のと同じになってしまいます。そこで、ライセンス本文そのものを
**ビルド成果物（Web版・APK版どちらも）に静的ファイルとして同梱し、
アプリ内の画面から完全オフラインのまま閲覧できる**ようにしています。

## 2. 生成スクリプトの使い方

ライセンス情報は `scripts/generate-licenses.mjs` というスクリプトで
自動生成しています。

```bash
pnpm run licenses
```

このコマンドは以下を行い、結果を `src/licenses/generated.ts` に書き出します。

1. `pnpm ls --prod --depth Infinity --json` を実行し、**実行時
   （production）依存として実際にビルドへ取り込まれるパッケージ**を、
   推移的依存も含めてすべて洗い出します（`--prod` により
   `devDependencies`、つまり vite・typescript・oxlint などビルド成果物に
   含まれないツール類は除外されます）。
2. 洗い出した各パッケージについて、`node_modules` 内の実ファイルから
   name / version / SPDXライセンス識別子 / 著作権者 / 配布元URL /
   **ライセンス本文全文**（`LICENSE` / `LICENSE.md` / `LICENCE` /
   `COPYING` など、大文字小文字・拡張子のゆらぎに対応）を読み取ります。
   ライセンス本文ファイルが見つからないパッケージ（例: `tr46`）は、
   `package.json` の `license` フィールドだけを記録し、本文欄には
   「ライセンス本文ファイルが同梱されていません」という日本語の注記を
   入れます。
3. npm の依存解決には出てこないが実際のビルド成果物に含まれる配布物
   （Android のネイティブ依存として組み込まれる ML Kit など）向けの
   手書きエントリ（4章参照）をマージします。
4. 名前順にソートし、TypeScript モジュールとして書き出します。

**再生成が必要なタイミング**: `dependencies`（`package.json`）を
追加・更新・削除したとき、または `pnpm-lock.yaml` の更新で推移的依存の
バージョンが変わったときは、`pnpm run licenses` を再実行し、
`git diff src/licenses/generated.ts` の内容をレビューした上でコミットして
ください。

生成物が最新かどうかを検証するだけのコマンドも用意しています（後述）。

```bash
pnpm run licenses:check
```

こちらはファイルを書き換えず、今コミットされている
`src/licenses/generated.ts` を再生成結果と比較し、差分があれば
非ゼロで終了します。CI に組み込んで「依存を更新したのにライセンス情報の
再生成を忘れている」ことを検知する用途を想定しています。

### なぜ `build` / `build:apk` の前段に自動で組み込まないか

ライセンス収集処理は `node_modules` 内の実ファイル（LICENSE本文など）を
読みに行く処理であり、依存パッケージのバージョンや構成によって
（ライセンス本文ファイルの有無・置き場所など）挙動が変わり得ます。これを
`build` / `build:apk` の必須経路に組み込んでしまうと、CI環境の
`node_modules` の解決状況次第で、本来失敗すべきではないビルドまで
巻き添えで失敗するリスクがあります。

そのため、ライセンス収集は開発者が依存を変更した際に手動で実行し、
生成物をレビューした上でコミットする運用とし、CI 側では
`pnpm run licenses:check` によって「生成物が最新か」だけを検証する
（＝再生成の実行そのものはCIにやらせない）方針にしています。

## 3. 生成物をリポジトリにコミットする理由

`src/licenses/generated.ts` は `.gitignore` に入れず、通常のソースファイルと
同様にリポジトリへコミットします。

理由は、CI（GitHub Actions / GitLab CI）や APK ビルドの実行環境が、常に
「そのつど `pnpm install` した後の `node_modules`」に依存しているためです。
ライセンス収集は `node_modules` の実ファイルを読みに行く処理であり、ここで
何らかの理由（パッケージの構成変更、CIのキャッシュの状態など）により
失敗し得ます。生成物を事前にコミットしておけば、ビルド自体は
「リポジトリの中身をそのまま固める」だけで完結し、再現性が高くなります。

言い換えると、ライセンス収集は「依存を変更するとき」だけ発生する
開発時の作業であり、「ビルドするたび」に発生する作業ではない、という
役割分担にしています。

## 4. npmの依存解決に出てこない配布物を手書きエントリで補っている理由

以前はここに `public/vendor/tesseract/` 以下（npm の依存解決を経由せず、
開発者が事前にダウンロードして手動配置していた tesseract.js の
Web Worker 本体・tesseract.js-core の WebAssembly 本体・Tesseract OCR の
英語学習済みモデル）の説明があった。tesseract.js を完全に削除し
`public/vendor/` 自体が無くなったため、この節の内容も現状に合わせて
書き換えている。

現在、手書きで補っているのは次の2件です。

- **Google ML Kit Text Recognition v2** — npm パッケージではなく、
  Android のネイティブ依存（Gradle の `com.google.mlkit:text-recognition`）
  として APK に静的リンクされます。`pnpm ls` の依存ツリーにはそもそも
  現れない（JavaScript側のラッパーである `@capacitor-mlkit/text-recognition`
  自体は npm パッケージとして自動収集の対象になっています）にもかかわらず、
  実際のビルド成果物（APK）には確実に含まれるOCRエンジン本体なので、
  漏らさず手書きで補っています。
- **zxing-cpp（`zxing_reader.wasm`）** — npm パッケージ `zxing-wasm` が
  内部に同梱している `zxing_reader.wasm` は、zxing-wasm 自体のコードでは
  なく、C++製バーコード読み取りライブラリ zxing-cpp を WebAssembly に
  ビルドしたものです。zxing-wasm 本体のライセンス（MIT）とは別の
  ライセンス（zxing-cpp は Apache-2.0）が適用されるため、区別して
  掲載する必要があります。

これらはいずれも `pnpm ls` の依存ツリーには出てこない（=
`scripts/generate-licenses.mjs` の自動収集では検出できない）にもかかわらず、
実際のビルド成果物には確実に含まれます。そこで、スクリプト内に
`MANUAL_VENDOR_ENTRIES` という定数配列として出自（どのOSSプロジェクトの
配布物か・ライセンス種別）を手書きし、npmパッケージから自動収集した
エントリとマージして一覧に含めています。

いずれも Apache License 2.0 が適用されるため、本文には Apache-2.0 の
正式な全文を収録し、冒頭に日本語で「どのファイルが、どのOSSプロジェクトの
配布物か」という出自の説明を添えています。

## 5. アプリ内のどこから見られるか

`src/ui/LicenseSheet.tsx` が、生成された `src/licenses/generated.ts` の
`LICENSES` 配列を読み込んで一覧表示する全画面パネルです。パッケージ名を
タップするとアコーディオン形式でライセンス本文が開閉します（本文は長いため、
既定では閉じた状態です）。`src/ui/HelpSheet.tsx`（使い方パネル）と同じ
構造・見た目を踏襲しており、`SimpleScanScreen.tsx` 側から
`React.lazy` + `Suspense` で別チャンクとして遅延読み込みする前提です。

ライセンス本文はいずれも翻訳・改変を行わず、配布されている原文（英語）の
まま掲載しています。ライセンス本文はライセンス契約の一部であり、
書き換えると効力に疑義が生じ得るためです。
